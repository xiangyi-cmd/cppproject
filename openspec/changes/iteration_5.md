# OpenSpec 變更紀錄：入住選單優化 (Iteration 5)

本文件紀錄了專案的第五次開發迭代流程，主要目標是優化「辦理入住 / 預訂房間」功能，由原本手動輸入房號，改為動態列出目前「空閒的客房」清單供使用者以方向鍵選取預訂。

---

## 1. 變更提案與目的 (Proposal)
* **目的**：提升入住預訂便利性。當使用者辦理入住時，系統自動篩選出所有「空閒（Available）」的客房，以方向鍵選單展示其房號、房型與基本價格；使用者直接選取即可開始輸入住客姓名與天數，不需手動輸入或查閱房態牆。
* **規格需求對齊**：
  - [x] 重構 [main.cpp](file:///c:/Users/go359/.gemini/antigravity-ide/scratch/cpp_hotel_booking/src/main.cpp) 的 `case 3` (辦理入住 / 預訂房間)：
    - 動態過濾出所有 `getIsBooked() == false` 的空閒客房。
    - 若無任何空房，提示「目前已滿房，無法辦理入住！」並返回。
    - 若有空房，以方向鍵選單顯示空房明細（如：`房號 101 (單人房) - $1000/晚`），並加入「返回主選單」選項。
    - 使用者選取後，自動顯示該客房詳細資訊，並繼續輸入住客姓名與天數以完成預訂。

## 3. 測試與驗證結果 (Verification & Test Cases)

### 測試案例 5.1：有空房時的入住選單與預訂
* **測試步驟**：
  1. 確保 101 單人房為空閒。
  2. 選擇「3. 辦理入住 / 預訂房間」。
  3. 使用方向鍵選擇 `房號 101 (單人房) - $1000 / 晚`，按 Enter。
  4. 輸入住客姓名 `王五`，天數 `3` 晚。
* **預期結果**：
  * 入住選單應正確列出 101 等所有空房，以及「返回主選單」選項。
  * 預訂成功後，101 房轉為已預訂。再次進入入住選單時，101 房已不在此選單中。
* **實際結果**：執行成功。選單正確顯示 101 等所有空房。選擇 101 房並輸入王五與 3 晚完成預訂後，101 房變為 [已預訂] 狀態，再次進入入住選單時已不再顯示 101 房，資料同步精確。

* **測試步驟**：將所有 6 間客房都辦理入住（使其全部為 booked 狀態），隨後進入「3. 辦理入住 / 預訂房間」。
