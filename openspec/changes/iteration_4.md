# OpenSpec 變更紀錄：退房選單優化 (Iteration 4)

本文件紀錄了專案的第四次開發迭代流程，主要目標是優化「辦理退房結帳」功能，由原本手動輸入房號，改為動態列出目前「已預訂的客房」清單供使用者以方向鍵選取退房。

---

## 1. 變更提案與目的 (Proposal)
* **目的**：提升退房便利性。當使用者欲辦理退房時，系統自動篩選出所有處於「已預訂」狀態的客房，以方向鍵選單展示其房號、房型與住客姓名；使用者直接點選即可退房，不需手動輸入或查閱房態牆。
* **規格需求對齊**：
  - [x] 在 [HotelManager](file:///c:/Users/go359/.gemini/antigravity-ide/scratch/cpp_hotel_booking/include/HotelManager.h#L23) 中新增 `getAllRooms()` 介面，供主程式獲取所有客房資料。
  - [x] 重構 [main.cpp](file:///c:/Users/go359/.gemini/antigravity-ide/scratch/cpp_hotel_booking/src/main.cpp) 的 `case 4` (退房結帳)：
    - 若無任何房間被預訂，提示「目前無任何已預訂的房間！」並返回。
    - 若有預訂房間，以方向鍵選單顯示已預訂房間的明細（如：`房號 102 (Single) - 住客: 張三`），並加入「返回主選單」選項。
    - 使用者選取後，自動執行退房與結帳。

## 3. 測試與驗證結果 (Verification & Test Cases)

### 測試案例 4.1：無房間預訂時的退房提示
* **測試步驟**：在所有客房皆空閒的情況下，選擇進入「4. 辦理退房結帳」。
* **預期結果**：系統應顯示「提示：目前沒有任何已入住的客房！」，並提示按 Enter 返回主選單。
* **實際結果**：執行成功。當資料庫中沒有任何預訂資料時，進入退房會提示「提示：目前沒有任何已入住/已預訂的客房！」，隨後可順暢返回主選單。

### 測試案例 4.2：有房間預訂時的選單展示與退房
* **測試步驟**：
  1. 預訂 102 單人房（住客：張三）。
  2. 預訂 301 總統套房（住客：李四）。
  3. 進入「4. 辦理退房結帳」，使用方向鍵選擇 `房號 301 (Suite) - 住客: 李四`，按 Enter。
* **預期結果**：
  * 退房選單應正確列出 102 與 301 房的預訂資訊，以及「返回主選單」選項。
  * 選擇 301 房後，系統應清屏並印出李四的退房結帳明細。
  * 301 房隨後成功釋放為空閒。
* **實際結果**：執行成功。退房選單以方向鍵形式精確列出兩間已預訂客房的資訊與返回選項。選取 301 房後，隨即清空畫面，印出李四的 $12,100 結帳清單，確認後該房已恢復為綠色的空閒狀態。
